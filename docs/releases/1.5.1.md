# Archive File 1.5.1-pl — исправления после аудита

23.10.2026. Пакет для MODX 2.8.x; целевая среда — MODX 2.8.5-pl / PHP 7.4.
Локальные проверки пройдены; подтверждения на рабочем сайте ещё нет.

## Изменения

| Область | Результат |
|---|---|
| Публикация | Перед переключением lastfile/parts записывается журнал. Следующая операция под source-lock сверяет SQL commit и возвращает прежний комплект либо сохраняет уже зафиксированный новый |
| Ошибки | Очистка не скрывает исходное исключение и не мешает unlock. При неудачном восстановлении журнал и резерв остаются для повтора |
| Удаление | Сначала файлы, затем SQL. При частичном сбое запись остаётся для повторного удаления; удалённые файлы не восстанавливаются |
| Обновление | Нет перепубликации файлов. Preflight, блокировки cron/источников, резерв кода/runtime и возврат файлов/метаданных при обрабатываемом исключении |
| БД | Аддитивные идемпотентные индексы events, пакетные запросы списка, отсутствие полного SHA-256 на list/cron-list |
| Журнал | Последние 200 попыток плюс актуальные heartbeat/warning/активные запуски; прерванные запуски определяются при получении lock |
| Выдача | Повреждённая историческая копия отвергается; размер сверяется с открытым файлом |
| API | Проверки scalar/ID/целых чисел/активности, буферизация JSON-ответа и диагностика ошибочного JSON; top-level обработка cron |
| Админка | Черновик сохраняется после fetch; предупреждение при закрытии/переходе; отключённая дата пуста при видимом общем столбце |
| XML | Legacy xmlMetadata использует потоковый парсер; deprecated entity-loader не вызывается на PHP 8 |
| Пакет | MODX >=2.8,<3 и PHP >=7.4; исключены runtime/storage/публичные выгрузки; symlink запрещён; воспроизводимый ZIP, lockfile и GPL notices |
| Проверки | Fault injection, настоящий SIGKILL до/после commit, canary-тест сборки, opt-in MySQL-тест и CI |

Сохранены три успешные копии, постоянные URL, правила XML, ежедневный режим,
ручная загрузка отключённого источника и оформление MODX 2.8.

## Проверки и границы

Локально: PHP 7.4 lint; сервис с ошибками публикации/очистки/commit; установка и обновление
в имитации MODX/SQLite; SIGKILL реального PHP и восстановление в новом процессе;
XML 26 128 078 байт / 8500 предложений / 9 частей / PHP heap limit 32 МБ;
jsdom 26.1.0 по lockfile; JS syntax; воспроизводимость ZIP, canary и равенство payload исходникам.

MySQL-тест и CI добавлены; локально MySQL отсутствует. Результат удалённого CI проверять
по конкретному commit. Тесты не заменяют настоящие MODX/браузер/Nginx, проблемный источник
и полный цикл cron. Подтверждение пользователя относится к интерфейсу предыдущей 1.5.0.

- Публичные URL не являются единым атомарным снимком: возможен краткий 404 частей или смешение версий во время переключения. Восстановление запускается следующей операцией с источником, не публичным GET.
- Потеря питания/диска, fsync и SIGKILL установщика не покрыты. После прерывания установки нужна повторная установка; резерв сайта остаётся необходимым.
- При невозможности вернуть код установщик сохраняет резервную папку и пишет путь в журнал MODX. Аддитивные таблицы/индексы при ошибке остаются.
- Старые бесхозные preview/tmp до 1.5.1 автоматически не удаляются. Новые временные архивные файлы принадлежат ID источника и очищаются под lock.
- Нужны проверка MODX/MySQL, права файлов, Nginx/CDN и EXPLAIN/IO на реальном объёме.
- MODX 3, отдельные права view/fetch/delete и глубокая проверка произвольных не-XML форматов остаются отдельными задачами.

## Обновление

1. Сохранить резерв сайта/БД, сначала проверить на копии сайта.
2. Дождаться окончания cron/ручного скачивания. При занятом источнике установщик откажет до замены кода; повторить позже.
3. Установить archivefile-1.5.1-pl.transport.zip через управление пакетами MODX и обновить страницу менеджера.
4. Проверить настройки, три копии, lastfile/parts, preview, ручную загрузку и CLI cron.
5. После ошибки удаления исправить права/диск и повторить действие; не удалять SQL-строку вручную.

Установщик не ротирует пользовательские данные. Создание индексов на большой events
может занять время; MySQL DDL и файлы не образуют общей транзакции.
Настройка серверных заголовков — в [DEPLOYMENT.md](../DEPLOYMENT.md).
