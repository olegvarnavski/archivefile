`runtime.php` генерируется установщиком с путём конкретного сайта; в Git его не хранить. Папки хранилища и реальные выгрузки также не входят в репозиторий.

## База

`{prefix}archivefile_sources`: ID, название, исходный URL, формат, enabled, последнее успешное скачивание, дата ежедневного запуска, ошибка, дата создания.

`{prefix}archivefile_copies`: ID, source_id, имя файла, время загрузки, generation_date, offers_count, размер и SHA-256. В текущем компоненте используется PDO-handle MODX и подготовленные SQL-запросы. `getConnection()` возвращает обёртку xPDOConnection, а не PDO; прямой вызов её `prepare()` запрещён.

Системные настройки: `archivefile.installed`, `archivefile.max_size_mb` (по умолчанию 50), `archivefile.storage_path`.

## Загрузка

1. Получить неблокирующий эксклюзивный lock источника.
2. Для cron проверить enabled и последний успешный ежедневный запуск.
3. Скачать во временный файл с лимитом размера и проверкой HTTP.
4. Для XML прочитать метаданные XMLReader, не разрешая DTD.
5. Сохранить новую закрытую копию; начать транзакцию SQL.
6. Добавить историю, обновить статус, убрать из БД копии сверх трёх.
7. Опубликовать lastfile через временный файл и rename; зафиксировать транзакцию.
8. Удалить устаревшие физические копии; освободить lock.

При обрабатываемом исключении до commit SQL откатывается, новая закрытая копия удаляется, прежний lastfile восстанавливается при необходимости. При ошибке сети или XML публикация не выполняется. Файловая система и SQL не образуют общей транзакции: аварийное завершение процесса требует отдельной сверки состояния, это задача развития.

Количество предложений — число элементов `offer` с атрибутом `internal-id`, включая дубликаты и пустые значения; это не число уникальных ID. Имена XML сравниваются с учётом localName. Дата берётся из `generation-date`; отсутствие даты не подменяется временем скачивания.

## API и доступ

POST-действия connector: `list`, `copies`, `save`, `fetch`, `delete`, `preview`. Требуются сессия `mgr`, право `settings` и session CSRF-токен. `fetch` освобождает блокировку PHP-сессии на время загрузки. Публичные исторические и lastfile-ссылки доступны без входа.

URL ограничены HTTP/HTTPS, портами 80/443, без user/password. Разрешаются публичные адреса; скачивание с локальных и служебных IP блокируется. Форматы задаются фиксированным списком. Код и системная конфигурация не публикуются в папке lastfile.

## Известные ограничения

- Нет индивидуального времени расписания на источник: время определяет cron.
- Исходные URL могут содержать токены. Не коммитить реальные настройки и выгрузки.
- Для не-XML форматов нет глубокого разбора содержимого; проверяется загрузка и явная HTML-ошибка.
- Работа 1.4.0 подтверждена пользователем; потоковое исправление 1.4.1 ещё ожидает проверки на проблемном источнике.
- Удаление источника после подтверждения удаляет историю и файлы. Не является обратимой операцией без резервной копии.

## Журнал и контроль

Таблица archivefile_events: имя и ID источника, kind (manual/daily/cron), статус (running/ok/error/skipped), время начала/окончания, duration_ms, размер, предложения, сообщение и warning. Страница показывает 100 записей; старые завершённые попытки очищаются после 200 последних событий, cron-записи сохраняются отдельно. Общий cron использует файловый lock. После аварии запись остаётся running; отсутствие свежего запуска видно по предупреждению.

## Настройки XML и разделение

archivefile_options: id источника и settings JSON. До 1.4.1 XmlTools выполнял DOM-разбор с запретом DTD и внешних сущностей, выбор по local-name и разрешённому пути контейнера. С 1.4.1 оболочка и предложения записываются во временные файлы на диске, затем каждая часть собирается последовательно; общие узлы и namespace сохраняются. Набор частей хранится рядом с архивной копией в .parts/, публичная копия — в parts/. Сначала подготавливается полный набор в скрытой папке, затем предыдущая parts/ переименовывается в резервную, новая занимает её место. После публикации полного lastfile фиксируется SQL. При обрабатываемом сбое возвращаются предыдущие parts/ и lastfile.

Замена каталога занимает два rename: во время переключения возможен краткий ответ 404. Это не единая атомарная транзакция файлов и SQL; авария процесса/питания требует сверки состояния. Не выдавать гарантии атомарного снимка сразу всех URL при одновременных запросах. Общие поля фида копируются без пересчёта внешних счётчиков или подписей. Для нестандартных подписанных XML может потребоваться отдельная адаптация.

## Обработка XML с 1.4.1

Парсер XMLReader работает с локальным файлом, DTD и внешние сущности запрещены. Подсчёт и preview не создают DOM фида. Разделение пишет оболочку XML без предложений и поток отдельных предложений во временные файлы; затем собирает каждую часть последовательно и проверяет её. Память ограничена текущим узлом/предложением и служебными данными. Временные потоки закрываются в finally. Общие метаданные сериализуются в UTF-8.

## Интерфейс 1.5.0

CMP-контроллер возвращает HTML и подключает mgr.css/mgr.js прежним способом. Оформление повторяет штатную тему MODX 2.8 без создания ExtJS-виджетов. CSS ограничен #archivefile-app, включая медиазапросы. Иконки используют FontAwesome менеджера без дополнительных сетевых запросов. У действий есть title и aria-label, у раскрытия — aria-controls/aria-expanded. Копирование cron использует существующий механизм clipboard/fallback.
