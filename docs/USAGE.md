# Руководство пользователя Archive File 1.5.0

## 1. Добавить источник

Открыть «Компоненты → Archive File», нажать «Добавить источник».

| Поле | Назначение |
|---|---|
| Название | Понятное имя, например «Основной каталог» |
| URL | Прямая ссылка HTTP/HTTPS без интерактивной авторизации |
| Формат | XML, CSV, XLSX, XLS, PDF, ZIP, JSON или TXT |
| Ежедневное скачивание | Разрешает обработку источника при запуске cron |

Сохранить настройки, затем нажать принудительное скачивание. Сохранение формы само по себе файл не загружает. Отключённый источник можно скачивать вручную.

## 2. Действия в таблице

| Действие | Результат |
|---|---|
| Шестерёнка | Открыть/закрыть настройки, части и историю под строкой |
| Обновление | Принудительно получить новую копию независимо от расписания |
| Скачать | Открыть ссылку на последнюю успешную историческую копию |
| Копировать | Скопировать постоянную ссылку lastfile |
| Удалить | После подтверждения удалить источник, архив и опубликованные части |

Подсказка при наведении уточняет назначение иконки. Открытый источник выделяется цветом. Настройки и история расположены друг под другом. Все ячейки выровнены по центру по вертикали.

Удаление не является отключением: для приостановки cron выключить ежедневное скачивание, сохранив источник.

## 3. XML-настройки

| Поле | По умолчанию | Поведение |
|---|---|---|
| Элемент предложения | offer | Локальное имя элемента, например item |
| Обязательный атрибут | internal-id | Считать только элементы с этим атрибутом; пустое поле — без фильтра |
| Элемент даты | generation-date | Первое найденное значение; пустое поле отключает показатель |
| Путь контейнера | Автоматически | Полный путь от корня из локальных имён через / |
| Создавать части XML | Выключено | Создавать части при превышении лимита |
| Максимум на часть | 1000 | Целое число от 1 до 100000 |

Пример:

```xml
<catalog>
  <updated>2026-10-23T10:00:00+03:00</updated>
  <offers>
    <item id="101"/>
    <item id="102"/>
  </offers>
</catalog>
```

Настройки: элемент `item`, атрибут `id`, дата `updated`, контейнер `catalog/offers`. Результат — два предложения.

Путь выбирает один контейнер, а предложения должны быть его непосредственными дочерними элементами. Без пути общий родитель определяется автоматически для разделения; разные родители требуют уточнения. Префиксы namespace не вводятся: используются локальные имена. Произвольный XPath не поддерживается.

Считаются элементы, не уникальные идентификаторы. Повторяющиеся значения и пустое значение присутствующего атрибута не исключают элемент. Если по правилам не найдено ни одного предложения, новая XML-копия отклоняется, прежний архив сохраняется.

Дата фида и время скачивания — разные показатели. Отсутствующая дата фида скрывается; время скачивания остаётся. Изменение XML-правил применяется к новым загрузкам, исторические показатели не пересчитываются.

## 4. Проверить до загрузки

Кнопка «Проверить настройки XML» использует текущие поля формы и временно скачивает исходник. Показывает:

- количество предложений;
- дату либо сообщение об её отсутствии;
- пример первого предложения;
- предполагаемое число частей.

Проверка не создаёт архивную копию, не меняет lastfile и не записывается как успешный запуск cron. После проверки сохранить форму и отдельно выполнить загрузку. Если предложений ноль — уточнить элемент, атрибут или путь контейнера.

## 5. Разделить фид

Включить разделение, задать лимит и сохранить. Части создаются при следующей успешной загрузке, если лимит превышен.

Для 2500 предложений и лимита 1000 получаются 1000 + 1000 + 500. Каждая часть — валидный XML с корнем, namespace и общими узлами исходника. Полный lastfile сохраняется отдельно.

```text
/assets/archivefile/17/lastfile.xml
/assets/archivefile/17/parts/part-001.xml
/assets/archivefile/17/parts/part-002.xml
/assets/archivefile/17/parts/part-003.xml
```

В админке у каждой части видны число предложений, размер, скачивание и копирование ссылки. При уменьшении выгрузки лишние части удаляются после успешного обновления. Если лимит больше либо равен числу предложений, остаётся полный файл без частей. Выключение разделения вступает в силу после следующей успешной загрузки.

Общие поля копируются без пересчёта сторонних счётчиков и цифровых подписей. Подписанному или нестандартному XML может понадобиться отдельная адаптация. Замена каталога частей занимает два rename; в момент переключения возможен краткий 404. Нельзя рассчитывать на единый атомарный снимок всех URL при одновременном обращении.

## 6. Копии и постоянные ссылки

Сохраняются три последние успешные копии каждого источника. Неизменившийся, но успешно полученный и проверенный файл тоже является новой копией.

Lastfile имеет постоянный адрес с ID источника; переименование источника его не меняет. Расширение зависит от выбранного формата. Изменение формата существующего источника запрещено — создать другой источник.

Историческая ссылка действует до ротации соответствующей копии. Ошибочные попытки остаются в журнале, но не занимают места среди трёх копий. Исторические наборы частей хранятся рядом с полными копиями в закрытом архиве; в интерфейсе показаны части последней успешной выгрузки.

Полные архивы лежат в core/components/archivefile/storage/ либо в настроенном хранилище. Lastfile и актуальные части — в assets/archivefile/{id}/. Публичные ссылки доступны без входа, в том числе обработчик исторических копий.

## 7. Настроить cron

Нажать «Копировать команду» в блоке расписания и вставить её в панель хостинга. Путь текущего сайта подставляется автоматически.

```sh
/usr/bin/php7.4 /home/user/site/public_html/core/components/archivefile/cron.php
```

Для 03:00 при московском часовом поясе cron: минуты 0, часы 3, остальные поля — *. Если панель принимает полную строку:

```cron
0 3 * * * /usr/bin/php7.4 /home/user/site/public_html/core/components/archivefile/cron.php
```

Для обычных абсолютных путей кавычек нет. Для путей с пробелами/специальными символами компонент сохраняет экранирование. Команда должна запускаться CLI PHP с нужными расширениями; версия PHP сайта может отличаться от CLI.

Источник обрабатывается не более одного успешного ежедневного запуска на дату по Europe/Moscow. Неудачная попытка может повторяться при следующем запуске. Ручное скачивание не зависит от ограничения. При параллельном запуске второй cron не начинает ещё одну обработку.

## 8. Читать журнал и предупреждения

Журнал показывает последние 100 событий: время, источник, ручной/ежедневный/общий запуск, статус, длительность, размер, предложения и сообщение.

| Статус | Значение |
|---|---|
| Успешно | Операция завершена |
| Ошибка | Посмотреть сообщение; ошибочная попытка не является копией |
| Выполняется | Начало записано, завершение пока нет; после аварии запись может остаться такой |
| Пропущено | Источник не требует нового ежедневного скачивания |

Для общего cron итог показывает число успехов, ошибок и пропусков. Ошибка одного источника не мешает попытке обработать остальные. Успешная ручная загрузка не доказывает, что cron настроен: проверять отдельный блок последнего cron.

По умолчанию отсутствие свежего запуска за 36 часов вызывает предупреждение. Падение предложений на 30% и более относительно предыдущей хорошей копии также вызывает предупреждение. Положительный фид с падением сохраняется; нулевой отклоняется. Уведомления сейчас видны в менеджере, автоматическая доставка в Telegram/email не реализована.

Старые ошибки после обновления не исчезают: смотреть время и результат новой попытки.

## 9. Системные настройки MODX

| Ключ | По умолчанию | Назначение |
|---|---|---|
| archivefile.cron_php_path | /usr/bin/php7.4 | Путь к CLI PHP для команды |
| archivefile.cron_stale_hours | 36 | Порог предупреждения об отсутствии cron |
| archivefile.drop_warning_percent | 30 | Порог падения количества предложений |
| archivefile.max_size_mb | 50 | Максимальный размер загрузки |
| archivefile.storage_path | Папка storage компонента | Путь закрытого архива |
| archivefile.installed | 1 после установки | Состояние компонента, управляется установщиком |

Путь хранилища не менять без переноса существующих файлов: автоматической миграции при ручной смене настройки нет. Обновления сохраняют имеющиеся значения настроек.

## 10. Диагностика

- **Недостаточно memory_limit** в старой версии: обновиться до 1.5.0, содержащей потоковый разбор из 1.4.1, и повторить загрузку. Очень большой отдельный XML-узел всё ещё может требовать памяти.
- **Ноль предложений:** проверить XML-поля и контейнер кнопкой предварительной проверки.
- **Ошибка HTTP/таймаут:** проверить доступность прямой ссылки с сервера. Предыдущие копии сохраняются.
- **Превышен размер:** проверить реальный размер и archivefile.max_size_mb.
- **Нет записи cron:** проверить путь PHP, команду, расписание, расширения CLI и вывод задачи хостинга.
- **Старое оформление:** очистить кеш MODX и выполнить Ctrl+F5.
- **Lastfile не обновляется во внешнем сервисе:** проверить timestamp/содержимое и кеширование CDN/Nginx. .htaccess действует только там, где его читает веб-сервер.

Для ошибки интерфейса собрать Console, запросы Network, версию пакета и шаги воспроизведения. Не удалять компонент и архив для диагностики.
