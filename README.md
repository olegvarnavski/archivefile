# Archive File для MODX Revolution

Скачивание файлов по прямым ссылкам, ежедневный архив и **три последние успешные копии каждого источника**. Управление — в разделе **«Компоненты → Archive File»**. Интерфейс оформлен в стиле штатного менеджера MODX 2.8.

**Текущая версия — 1.5.0.** Пользователь подтвердил улучшенный интерфейс на сайте. Обработка большого XML из проблемного источника после потокового исправления ещё ожидает отдельного подтверждения.

[Скачать установочный пакет 1.5.0](packages/archivefile-1.5.0-pl.transport.zip) · [Руководство пользователя](docs/USAGE.md) · [Описание выпуска](docs/releases/1.5.0.md)

## Что умеет компонент

- Несколько источников с произвольными названиями и прямыми HTTP/HTTPS-ссылками.
- XML, CSV, XLSX, XLS, PDF, ZIP, JSON и TXT.
- Ежедневная загрузка через cron, включение и отключение расписания на источник.
- Принудительная загрузка независимо от расписания и совпадения содержимого.
- Три успешные копии: реальный файл, непустой размер и проверка SHA-256.
- Для XML — настраиваемый элемент предложения, необязательный атрибут, элемент даты и путь контейнера.
- Проверка XML-настроек до сохранения: дата, количество, пример предложения и расчёт частей.
- Разделение большого XML по задаваемому числу предложений с сохранением общего корня, пространств имён и общих полей.
- Постоянный lastfile, ссылки на исторические копии и отдельные части.
- Журнал попыток, контроль cron и предупреждения о падении количества предложений.
- Настройки, части и история раскрываются под строкой источника. Кнопки имеют подсказки и доступные подписи.

Полный файл:

```text
https://example.org/assets/archivefile/17/lastfile.xml
```

Части при включённом разделении:

```text
https://example.org/assets/archivefile/17/parts/part-001.xml
https://example.org/assets/archivefile/17/parts/part-002.xml
```

При лимите 1000 и 2500 предложениях получаются части **1000 + 1000 + 500**. Полный файл сохраняется всегда. Если число предложений не превышает лимит, части не создаются.

## Установка и обновление

Требования: **MODX Revolution 2.8.5-pl**, **PHP 7.4+**, cURL, DOM, XMLReader, PDO MySQL, права на запись и возможность запуска CLI PHP через cron. Другие версии MODX отдельно не проверены.

1. Сохранить резервную копию сайта и БД или использовать тестовую копию.
2. Скачать [archivefile-1.5.0-pl.transport.zip](packages/archivefile-1.5.0-pl.transport.zip).
3. Загрузить пакет через установщик MODX и установить. Существующий компонент обновить **без удаления**.
4. Очистить кеш MODX, перезагрузить менеджер Ctrl+F5.
5. Открыть «Компоненты → Archive File», добавить источник или открыть существующий.
6. Для XML проверить настройки, сохранить и выполнить ручную загрузку.
7. Проверить журнал, lastfile и части, затем настроить cron.

Источники и настройки сохраняются. Лишние старые копии удаляются при ротации после успешной загрузки, а не во время установки. Демонстрационные ссылки не добавляются.

## Cron

Компонент выводит готовую команду с путём текущего сайта и кнопкой **«Копировать команду»**. Обычные пути выводятся без кавычек:

```sh
/usr/bin/php7.4 /home/user/site/public_html/core/components/archivefile/cron.php
```

Если cron хостинга использует московское время, ежедневное расписание в 03:00:

```cron
0 3 * * * /usr/bin/php7.4 /home/user/site/public_html/core/components/archivefile/cron.php
```

В панели хостинга расписание и команда могут вводиться отдельно. Путь сайта в примере заменить своим; готовая команда в компоненте уже содержит нужный путь. PHP CLI меняется настройкой `archivefile.cron_php_path`. Пути с пробелами или специальными символами экранируются безопасно.

Компонент учитывает успешный ежедневный запуск по `Europe/Moscow`; часовой пояс самого cron определяется хостингом. Ручная загрузка не подменяет статус запуска cron.

## Как защищён архив

Ошибка HTTP, пустой ответ, некорректный XML или ноль предложений по настройкам источника **не заменяют lastfile и не вытесняют успешные копии**. Ошибка остаётся в журнале.

Для других форматов понятия «предложение» нет: проверяются успешная непустая загрузка и явная HTML-ошибка, глубокая проверка форматов не выполняется.

XML с DTD и внешними сущностями запрещён. Скачивание с локальных и служебных IP блокируется. Управление требует сессии менеджера, права `settings` и CSRF-токена.

Исторические копии хранятся в закрытой папке. Их ссылки, lastfile и части доступны без входа: архивировать таким способом следует данные, которые допустимо выдавать по публичной ссылке. Ссылка на историческую копию работает только пока она сохранена.

## Большие XML

С 1.4.1 XMLReader читает файл последовательно, без DOM всего фида. Для разделения оболочка документа и предложения записываются во временные файлы на диске. В памяти находится текущий узел или предложение, а не весь XML.

Проверено локально: **26 128 078 байт, 8500 предложений, PHP memory_limit=32M**, восемь частей по 1000 и одна на 500. Пиковая PHP-куча в тесте — 2 097 152 байт; это не общий RSS процесса/libxml. Синтетический тест не является подтверждением работы конкретного источника на сервере.

Нужно свободное место для временных файлов. Очень большой отдельный узел всё ещё может потребовать больше памяти. Лимит загрузки — 50 МБ по умолчанию, меняется через `archivefile.max_size_mb`.

## Разработка и проверки

```sh
python3 build/build.py
php tests/service.php
php tests/install.php
php tests/large-xml.php
npm install
npm test
```

Пакет создаётся в `dist/archivefile-1.5.0-pl.transport.zip`; исходники и тесты включаются в `SOURCE`. Для PHP-тестов дополнительно нужен PDO SQLite. Установочный тест использует штатный xPDO vehicle с имитацией MODX и SQLite. UI-тест работает в jsdom и включает конфликтующий ID меню MODX.

Локальные тесты не заменяют установку на настоящем MODX/MySQL и проверку браузера. Изменения делать небольшими ветками с понятным описанием проблемы, поведения, проверок и ограничений.
