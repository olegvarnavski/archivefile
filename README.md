# Archive File для MODX Revolution

Компонент MODX для скачивания файлов по прямым ссылкам, ежедневного архивирования и хранения последних **трёх успешных копий каждого источника**. Источники добавляются через менеджер MODX: своей ссылке можно задать понятное название, включить расписание и скачать файл вручную.

## Версия 1.4.0 — настройки и части XML

Для каждого источника: имя элемента предложения, необязательный атрибут, элемент даты, путь контейнера, включение разделения и максимум предложений на часть (1–100000, по умолчанию 1000). Стандартные значения: offer / internal-id / generation-date. Пустой атрибут означает считать все выбранные элементы. Пустая дата отключает её; отсутствующая дата скрывается автоматически.

Путь контейнера состоит из локальных XML-имён, например `realty-feed` или `catalog/offers`. Пространства имён учитываются через local-name. Произвольный XPath не выполняется. Если контейнер не задан, общий непосредственный родитель определяется автоматически. Предложения в разных контейнерах требуют явной настройки. Для сложного XML поддерживается один общий непосредственный контейнер выбранных предложений.

«Проверить настройки XML» скачивает временную копию без изменения архива, lastfile и журнала запусков. Показывает число предложений, дату, пример элемента и расчёт частей.

Разделение выполняется только при превышении лимита. 2500 предложений при лимите 1000 дают 1000 + 1000 + 500. Полный файл сохраняется всегда. Части: `/assets/archivefile/{id}/parts/part-001.xml`, `part-002.xml` и т. д. Дата и прочие общие поля сохраняются вместе с корневым элементом и namespace. Для каждой части повторно проверяется XML и число предложений. Предыдущий набор частей сохраняется при обрабатываемой ошибке публикации; устаревшие части удаляются после успешной замены. Выключение разделения очищает публичный список частей после следующей успешной загрузки.

Архивируются полные файлы (три успешные копии); соответствующие наборы частей также лежат в закрытом архиве. В менеджере отображаются части последней успешной выгрузки, скачать или скопировать ссылку можно отдельно на каждую часть. При смене XML-настроек старые показатели копий остаются историческими; новые правила применяются к новым загрузкам.

Требуется PHP DOM. Очень большой XML требует достаточного memory_limit: перед DOM-разбором проверяется доступный бюджет памяти; при недостатке загрузка отклоняется с объяснением, старый архив остаётся. Локальные PHP 7.4/SQLite/jsdom проверки пройдены; установка на реальном MODX/MySQL ещё нужна.

## Версия 1.3.0

Хранятся три успешные копии. Проверяются реальный файл, размер и SHA-256. Пустой ответ, ошибки HTTP/XML и XML с нулём offer internal-id не заменяют архив и lastfile. Ошибочные попытки видны в журнале, а не среди копий. Старые лишние копии физически удаляются после следующей успешной загрузки соответствующего источника, не при установке.

Добавлены отдельный контроль cron и журнал (последние 100 записей на странице): время, источник, способ запуска, статус, длительность, размер, предложения и причина ошибки. Ручное скачивание не обновляет статус cron. По умолчанию отсутствие запуска за 36 часов вызывает предупреждение; archivefile.cron_stale_hours меняет порог. Снижение количества предложений на 30% и более вызывает предупреждение; archivefile.drop_warning_percent меняет порог. Положительный фид с резким падением сохраняется, нулевой — отклоняется. Для не-XML нет понятия предложений; принимается успешно скачанный непустой файл с существующими проверками.

## Исправление 1.2.1

Установлена причина ошибок интерфейса: пункт меню MODX и контейнер компонента имели одинаковый ID archivefile. Контейнер переименован в archivefile-app; логика скачивания не меняется. Регрессионный тест включает пункт меню с прежним ID. Проверка на сайте после установки ещё требуется.

## Возможности 1.2.0

- Несколько прямых HTTP/HTTPS ссылок с произвольными названиями.
- XML, CSV, XLSX, XLS, PDF, ZIP, JSON и TXT.
- Ежедневная загрузка через cron; выключение расписания для отдельных источников.
- Принудительная загрузка, включая отключённые источники и неизменившиеся файлы.
- Последние три успешных копии, размер, время загрузки и статус ошибки.
- Для XML: `generation-date`, число элементов `offer` с атрибутом `internal-id`, изменение числа предложений между копиями.
- Настройки и история раскрываются под строкой источника: сначала **«Настройки источника»**, затем **«Последние 3 копии»**.
- Иконки с подсказками: настройки, обновить, скачать, копировать, удалить.
- Удаление источника вместе с его архивом после подтверждения.
- Вертикальное выравнивание ячеек по центру и прокрутка страницы.
- Обычный публичный файл последней успешной версии:

```text
https://example.org/assets/archivefile/17/lastfile.xml
```

ID источника задаёт папку, расширение соответствует формату. Переименование источника не меняет адрес. Исторические копии выдаются через `assets/components/archivefile/file.php?source=17&copy=123`.

## Требования

- MODX Revolution 2.8.5-pl — целевая версия.
- PHP 7.4+ с cURL, DOM, XMLReader и PDO MySQL.
- MySQL, поддерживаемый целевой установкой MODX.
- Права PHP на запись в папки компонента и `assets/archivefile/`.
- Возможность запуска CLI PHP по расписанию хостинга.

Другие версии MODX отдельно не проверены. Минимальная версия PHP описывает совместимость компонента, а не срок поддержки самого PHP.

## Установка и обновление

1. Сохранить резервную копию сайта и базы или использовать тестовую копию.
2. Загрузить `packages/archivefile-1.4.0-pl.transport.zip` через установщик пакетов MODX.
3. Установить пакет; для существующего компонента выполнить обновление без удаления.
4. Очистить кеш MODX и перезагрузить менеджер `Ctrl+F5`.
5. Открыть **«Компоненты → Archive File»**.
6. Добавить источник, выбрать формат, выполнить ручную загрузку.
7. Проверить дату, счётчик, скачивание исторической копии и постоянный `lastfile`.
8. Добавить команду из блока расписания в cron.

Обновления 1.1.4 и 1.2.0 не удаляют источники и архивы. Демонстрационные ссылки автоматически не добавляются. Пакет создаёт собственные таблицы, namespace, пункт меню и системные настройки; ресурсы, шаблоны и чанки публичного сайта не меняются.

**Важно про старые версии:** установщики 1.1.0–1.1.1 удаляли неизменённый первоначальный источник вместе с архивом. Уже удалённые данные возвращаются только из резервной копии; исходную ссылку можно добавить заново для последующих загрузок.

## Cron

Команда в интерфейсе использует `/usr/bin/php7.4` и фактический MODX_CORE_PATH. Путь к PHP можно изменить системной настройкой `archivefile.cron_php_path`; обновления сохраняют её значение. Пользователь сообщил, что 1.2.1 работает после исправления ID меню.


Пример команды:

```sh
/usr/bin/php /полный/путь/core/components/archivefile/cron.php
```

Пример расписания:

```cron
0 3 * * * /usr/bin/php /полный/путь/core/components/archivefile/cron.php
```

Пример означает 03:00 **в часовом поясе cron хостинга**. Для 03:00 по Москве выбрать соответствующее время в панели. Компонент использует `Europe/Moscow` для дат и ограничения одного ежедневного успешного запуска на источник. Ошибки могут быть повторены следующим запуском. Ручная загрузка не блокируется этим ограничением. Использовать CLI PHP с нужными расширениями; версия PHP сайта и CLI может отличаться.

## Хранение и ссылки

Основной архив расположен в закрытой папке `core/components/archivefile/storage/` или по настройке `archivefile.storage_path`. Последняя копия дополнительно публикуется в `assets/archivefile/{id}/lastfile.{format}`. Публичный файл доступен без сессии менеджера; включать эту функцию только для файлов, которые можно отдавать по открытой ссылке.

Историческая ссылка перестаёт работать после удаления копии при ротации. Постоянный адрес обновляется после успешной загрузки. Отключение ежедневного скачивания не удаляет файл. Смена формата существующего источника в 1.2.0 запрещена для сохранения адреса — добавить другой источник.

Для Apache компонент записывает правила запрета просмотра каталога и `Cache-Control: no-cache`. Nginx и CDN не читают `.htaccess`: исключить эту папку из длительного кеширования на уровне сервера, если оно используется.

## Разработка

```sh
python3 build/build.py
php tests/service.php
php tests/install.php
npm install
npm test
```

Сборка создаёт `dist/archivefile-1.4.0-pl.transport.zip`. Исходники и тесты включаются в пакет в папку `SOURCE`. Проверка установщика использует штатный xPDO script vehicle с имитацией MODX и SQLite; фикстуры в `tests/fixtures/modx`. Для тестов PHP нужен также PDO SQLite. UI-тест использует jsdom и имитацию ответов API.

Дополнительно проверить синтаксис всех PHP-файлов именно на PHP 7.4. Перед каждым выпуском обязательна ручная проверка на тестовом MODX/MySQL. Полный перечень проверок — [docs/TESTING.md](docs/TESTING.md).
